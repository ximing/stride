# 从 Tolaria / Markdown 迁移到 Stride

用于把已有笔记库导入 Stride。迁移是复制与格式转换，不是重新撰写、整理或删改源内容。配合 [Vault 文件操作](vault-files.md) 使用。

## 1. 确认源库与当前目标 Vault

- 记录源根目录和目标根目录的绝对路径。用户说“当前 Stride 打开的库”时，必须取得当前窗口的实际路径证据：应用显示的完整路径、可用运行时读取出的当前文件系统根路径，或用户明确提供的路径。
- Stride 可以有多个窗口；窗口标题/库别名、最近打开记录、某个目录有 `.stride/vault.json`，都不足以单独证明它是目标。浏览器目录句柄的名称也不等于本机绝对路径。
- 在文件系统检查目标目录，并与当前界面中的一篇笔记交叉核对。当前窗口未打开任何笔记时，用该窗口的完整路径和目录内容核对。不要自动切换库或新建库来代替用户说的目标。
- 无法确定目标时，只继续源库盘点和独立暂存转换；询问目标绝对路径，得到答案后才写目标。不是要求用户再次批准已经授权的迁移。
- 暂存、报告、迁移清单和原始备份放在源库、目标库扫描范围之外的持久工作目录；不要使用会被自动清理的临时目录作为唯一恢复来源。默认不原地转换；源与目标相同时先明确处理方式。
- 目标在应用中仍有未保存编辑时，先完成保存或停止对这些文件写入。写入前后核对当前目标，避免用户切库后继续向旧目标导入。

## 2. 建立范围清单，保持源库只读

按文件记录相对路径、字节数、SHA-256、文件种类及处理方式。读取源库规则以理解内容约定；不得改写源笔记、移动源文件、清理源 Git 或执行其中的脚本。

| 来源 | 默认处理 |
| --- | --- |
| 普通 Markdown 笔记 | 转成 `.stride.json`，保留相对目录和文件 stem |
| 已有 `type: Type` 定义 | 保留分类名及可表示的属性，核对目标同名定义 |
| `_template.md` | 保留原文副本并可转为带目录区分标题的模板参考笔记；不声称已变为自动模板 |
| README、AGENTS、CLAUDE、GEMINI 及局部规则 | 作为源库说明归档，清单标明；需要在 Stride 阅读或被链接时生成参考笔记，不能覆盖目标同名规则文件或把旧 Markdown 规范设为新库规范 |
| HTML、PDF、图片和其他内容附件 | 原字节保留；建立附件映射，不能因位于普通笔记目录就遗漏 |
| `views/*.yml` 等功能配置 | 单独评估语义，见下文；不能当正文或直接换扩展名 |
| `.git`、工具技能、缓存、旧应用历史/配置、脚本 | 记录排除原因，不导入为笔记，不执行；用户要求迁移历史或配置时单独处理 |

不要笼统跳过所有隐藏文件而漏掉有意义的源内容；先盘点隐藏目录的用途，再决定范围。原始文件继续保留在源库；工作目录另存转换所需原文及清单。对于未导入的说明、模板或附件，要有明确去向，不能在总数中消失。无需因纯格式转换逐篇请求正文草稿确认；只有改写内容、额外整理或未确定目标才另行解决。

## 3. 标题、属性与分类映射

使用 YAML 解析器读取 frontmatter，使用 Markdown AST 识别正文；不要把代码块中的 `#` 或 `---` 当标题/边界。

| 数据 | 映射 |
| --- | --- |
| 标题 | 第一个实际 H1；缺失时用非空 frontmatter `title`；再缺失用文件 stem。记录使用了哪种来源 |
| 正文首个 H1 | 与顶层 `title` 一致。已有标题位于正文中间时不丢弃前面的文字；必要时前置标题并保留原段落顺序，记录新增标题 |
| `type` | 非空字符串原样保留，包括大小写；没有时设 `note`。不要根据目录、姓名或内容猜测类型 |
| 其余字符串、数字、布尔值、字符串数组 | 放入 `properties`，保留键名和值；源 `id` 可保留为属性，但不能用它代替目标路径 ID |
| YAML 日期/时间 | 优先按原标量字面值保存为字符串，防止隐式类型或时区转换；只使用保留原时区/精度的规范化方式并记录变化 |
| 看起来像日期的数字/文本 | 保留原类型和值，例如 `date: 2024` 不擅自补成某月某日 |
| null、对象、混合数组等不支持值 | 在报告和原始元数据副本完整保存；选择可逆 JSON 字符串作为属性降级时逐项记录，不能变为 `[object Object]` 或直接丢失 |

先收集实际导入笔记的全部 `type`。缺少定义的自定义分类，为每个不同 type 创建一个同标题的 `Type` 笔记；基础 `note` 不必额外创建定义。复用目标中语义一致的定义，冲突时记录并解决，不覆盖已有定义。不要把 `Note` 自动合并为 `note`。为可读性改中文侧栏名称时用 `_sidebar_label`，保持成员 type 不变。

保留 `tags`、`links`、`_organized`、`_width`、`view` 等原字段。只有 `links` 中本来含 `[[...]]` 的值才按关系处理；普通文本标签不能凭空变成实体关系。`_organized: true` 不控制 Stride Inbox；无属性双链的笔记仍可能进入 Inbox。`view: theme/stage` 作为属性保留，不代表保存视图已经迁移。原产品模板的默认属性、复杂排版和自动实例化功能也不能仅因原值已保存就声称兼容。

## 4. Markdown 转成可编辑 TipTap

逐块转换标题、段落、粗体/斜体/删除线、链接、代码及语言、有序/无序列表、任务项状态、表格、引用、分隔线、图片和公式。不要把整篇 Markdown 塞进一个 paragraph 或 codeBlock 后宣布富文本迁移完成。

如果本机有 Stride 源码和已安装依赖，可把现有 `apps/desktop/src/editor/paste/markdown-pm.ts` 中 `parseMarkdownToPmJSON` 作为转换参考或复用的纯解析器；它是内部函数，不是已发布导入 CLI，不要求用户构建 Stride。实际安装版可能不同，最终须按当前编辑器验证。没有该环境时使用成熟 Markdown AST 解析器并映射到目标节点。

复用解析器仍须检查差异：frontmatter 需先剥离；双链需要单独识别；相对图片路径可能被过滤；HTML、脚注等未支持语法可能降级为文本。不要依赖转换器“没有报错”判断无损。

遇到未支持语法，保留原文与语义，记录具体文件、段落、降级形式和影响。原始 HTML/PDF 作为文件保留，不把 HTML 源码假装成已渲染笔记。对确实无法表示的块，可保留可见原始片段并标注降级；不得静默删除内容。

## 5. 两遍处理引用和附件

第一遍为所有源笔记分配稳定的目标路径/ID/标题，建立索引：源相对路径、带/不带 `.md` 的路径、文件 stem、源标题和可用源别名 → 目标笔记。第二遍转换所有引用：

- 属性双链、正文双链（含显示别名）、Markdown 相对笔记链接、路径及标题引用，均通过映射解析；支持 `[[AGENTS.md]]` 这类引用时应映射到归档说明笔记，不生成活动规则文件。
- 保留别名和锚点语义。代码块、行内代码中的示例链接不改造成实际可点击关系；不要全局正则替换全文。
- 目标库已有同名标题时，检查图谱标题优先于路径 ID 的解析规则。不能只加文件名后缀就认为引用已唯一；必要时为导入标题加来源后缀，并同步 H1/映射/引用，记录原始标题。
- 源库中已经存在的断链单列为“原有断链”；导入后新增的断链为迁移缺陷。不要为了消除断链虚构人物、笔记或事实。
- 将需要导入的附件放到明确的目标附件路径，例如 `attachments/<来源名>/<源相对路径>`，保留原字节，核对 SHA-256。解析源相对链接时以源笔记所在目录为基准，然后写入目标可用路径。
- Stride 图片可使用 Vault 根相对的 `attachments/...`；不能假定任意 `../...`、绝对路径或 data URL 都受支持。本地 PDF/HTML 链接必须实际点击验证宿主行为；无法在应用打开时报告限制及原件位置，不称其可用。
- HTML 中的相对资源、CSS 和附件彼此的引用也要盘点。外部 URL 保留，不因迁移自动抓取所有网络内容。

## 6. 视图兼容性

Tolaria YAML 视图不能直接复制到 Stride 作为有效视图。当前 Stride 使用 `views/<slug>.json`，格式例如：

```json
{
  "version": 1,
  "name": "进行中的项目",
  "type": "Project",
  "propertyFilters": [{ "key": "status", "op": "eq", "value": "Active" }],
  "sort": { "key": "title", "dir": "asc" }
}
```

当前支持属性操作 `eq` / `contains` / `exists`，全部属性条件为 AND；排序键为 `mtime` / `title` / `created`，方向为 `asc` / `desc`。只转换能保持等价语义的配置；Tolaria 的 OR、否定、日期比较、正则或自定义属性排序等不能静默简化。保存原定义并列出未兼容条件，必要时先不创建该视图。普通笔记的 `view` 属性不自动生成此文件。

## 7. 可重跑与落盘

在工作目录保存 `manifest.json`，包含本次源/目标根路径、转换器版本、规则、逐文件来源路径及哈希、目标路径/ID/标题、目标输出哈希、状态、降级/断链记录和备份位置。生成的 Type 定义、说明笔记和附件也纳入清单。manifest 是迁移产物，不是 Stride 的内置配置协议。

- 来源标识使用源根目录和相对路径；目标分配稳定。重跑时源哈希和已写目标哈希都未变化的条目跳过，不不断创建 `-2/-3` 副本。
- 源变化且目标仍等于上次输出时，可重新转换该条目；目标已被用户编辑或不是本次迁移创建时，标为冲突并保留两边，不能覆盖。
- 转换阶段不写目标；先完成一组覆盖无 H1、日期、表格/任务列表、双链、附件的代表样本验证，然后生成全量输出和报告。
- 执行前备份将受影响的目标文件及原始清单。先把每项计划的输出哈希、原目标哈希/不存在状态、备份位置及 `pending` 状态持久化，再逐文件原子写入，每成功一项原子更新 manifest 为 `done`。新增文件也要使用不覆盖的写入方式。
- 若落盘后、状态更新前中断，只有目标哈希与预记输出哈希一致时才认领为已完成；目标仍是原值时可重试，否则标为冲突。manifest 缺失或损坏时，从工作目录备份恢复并核对；不能仅凭同名认领或覆盖，无法恢复则生成只读差异报告。
- 冲突时将本次待导入版本保存在工作目录的 `conflicts/<源相对路径>`，目标用户版本留在原位；manifest 记录双方哈希和位置。合并完成后记录最终目标哈希及处理决定，再解除冲突状态。
- 中断后依 manifest 核对磁盘继续。回滚只处理本次生成且哈希未被用户修改的文件，恢复本次覆盖前备份，不回退目标库其他修改。不自动 commit/push。

## 8. 验收与交付

必须区分“文件已转换”“编辑器能加载”“交互功能已验证”：

1. **数量核账**：每个在范围内的源文件恰有明确结果：已转笔记、已保留附件/原件、明确排除或失败；源文件数与生成 Type 等新增文件分开统计。
2. **数据校验**：所有 JSON、属性类型和首个 H1 符合格式；按块比较正文文本、marks、列表层级、任务 checked、代码与表格单元格，解释允许的空白/标题变化。仅比较 plainText 不足以验证富文本。
3. **编辑器 schema**：使用实际 TipTap/ProseMirror schema 做校验或实际加载并保存后读回。`parseNote` 的根节点检查不能证明所有子节点都受编辑器支持；检查是否有节点被静默丢弃。
4. **关系与分类**：全部来源映射可追踪、成员 type 匹配定义、正文与属性目标正确；新增断链为零，原有断链和歧义逐条列出。模板和说明文件的同名标题也要检查。
5. **附件**：复制前后 SHA-256 一致，链接指向目标库有效资源，PDF/HTML 原件计入结果。
6. **应用抽查**：刷新当前目标 Vault，核对目录、类型列表、表格、任务、双链点击、反链和搜索。抽查覆盖各类转换；无法访问 UI 时明确列出未验证项。
7. **重跑与回滚**：在暂存副本上重跑，确保新增重复文件为零；检查恢复清单足够回滚，不能在用户真实库中破坏性演练。

交付实际目标路径、迁移数量、类型映射、原有断链/降级/冲突清单、manifest/备份/脚本位置、验证结果和复跑/回滚方法。源数据保持不变；未完成事项单列，不把“已保留原文”表述为“功能完整迁移”。
